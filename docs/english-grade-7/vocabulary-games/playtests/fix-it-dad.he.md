# פלייטסט הסדנה

## מעבר ראשון

`npm test -- tests/unit/fixItDad.test.ts` נתן RED עם מודול חסר ו־GREEN ‏(1) לאחר מימוש התנאים לתיקון ולשתי תושבות. `npm run build` עבר. בסיבוב Chromium הראשון אבא לא הצליח להרים את המזוודה, הסרת הידית יצרה תקלה מובנת, והחזרתה והצבת השלט בימין אפשרו לפתוח אותה. בדיקת הכיסוי בסיום לא עברה בהרצה הראשונה. הרצף הורץ שוב לאיסוף צילום לפני השיפור, עם צילום ישיר בסיום, ועבר (1). הצילומים `1024-initial-blocked.png`, `1024-initial-repair.png` תחת `output/playwright/vocabulary/fix-it-dad/`.

הבקשה לתיקון נשארה זהה גם אחרי ההצלחה והמשוב לא נשמר כשחוזרים לערוך. היה אפשר לבצע פעולה הפוכה כדי לחזור צעד, אך לא היה ביטול ישיר. לוח התגים הוסיף שטח לאותה עמודה והסיח מעולם החיבורים. הציור במזוודה הפתוחה נראה בעיקר כמכסה ריק. אלה תצפיות מסיור סוכן, ללא ילדים.

## שינוי ומעבר שני

בדיקת הביטול החזירה RED עם פעולה לא מוכרת ו־GREEN ‏(2) אחרי הוספת צעד ביטול במודל. נוסף מצב השלמה שנשאר אחרי עריכה, נוסף ציור אביזרים במכסה, ולוח התגים קיבל מסך רשות עם שני ציורים שמתגלים. התיקון והתגים משתמשים באותה שמירת פעולות, בלי שער ביניהם. סעיף המסירה ב־GDD מפרט את הביטול, השחזור והאיור.

`npm run test:e2e -- fixItDad` עבר (4). בכל גודל נבדקו תקלה, תיקון, עזרה, ריענון, Enter, השלמה ויציאה. נבחרו שתי תושבות, נפתחו שני תגים בחלק מהריצות ונבדקה יציאה בלעדיהם. בדיקה נוספת שמרה במכוון רצף בלתי אפשרי וחסמה כתיבה, והמשחק הראה שתי הודעות מתאימות ונשאר פעיל עד תיקון. צילומי הגרסה השנייה נשמרו ונבדקו תחת אותה תיקיית פלט.

בפלייטסט אנושי: האם ילדים בודקים שימוש לפני ההצבה, והאם הרמת המזוודה מסבירה לבד את ההבדל? השוו את אותה תקלה עם ובלי מצב הרמה נראה אחרי בדיקה, עם אותם כפתורים ובקשות.
