# פלייטסט אבידות

## מעבר ראשון

ב־`npm test -- tests/unit/lostFound.test.ts` התקבל RED עם מודול חסר, ואחרי הוספת כללי הבירור התקבל GREEN ‏(1). `npm run build` עבר. `npm run test:e2e -- lostFound` הריץ Chromium בפורט 5186 ועבר (1). הסוכן מסר צעיף שגוי ותיקן, ניסה למסור תיק כששני התיקים התאימו, בדק תג, שאל על המקום וסיים בעזרת הדגמה. אין משתתפים אנושיים. נשמרו ונבדקו `initial-correction.png` ו־`initial-bags.png` תחת `output/playwright/vocabulary/lost-found/`.

ב־1024×600 שולי הפאנל הגיעו מעבר לתחתית. בזוג הצעיפים הדוגמה המאוירת לא הייתה מובחנת מספיק. תג מקום מבודד דורש לזכור היכן נמצא כל תיק. אחרי המסירה אותו חפץ הוצג שוב, בלי להמחיש מה השתנה לנוסע. אלה תצפיות על הממשק ושיפוט עיצובי.

## שינוי ומעבר שני

נבדק RED נוסף כשהבדיקה ציפתה לשחזור תג פתוח וקיבלה `null`; אחרי שילוב פעולת בדיקה ב־reducer התקבל GREEN ‏(2). קוצר הריווח בגובה קטן, תוקנה וריאציית הנקודות, אחרי בירור נראים שני התגים, ואיור תוצאה מציג את שימוש הנוסע. סעיף המסירה ב־GDD מתעד את הפעולות השמורות, האיור והתמיכה; README מתעד את גבולות השמירה והדיווח.

במעבר Chromium השני הורצו שלוש גרסאות מסך (1024×600, 1280×720, 1440×900). נבדקו בחירה שגויה ותיקון, בירור, ריענון וחזרה דרך Enter, הדגמה במקלדת, תוצאה ויציאה למשחקונים. בדיקות פריסת הכפתורים כוללות אבות חותכים. אין פעמונים גם בסיום. הצילומים לפי רוחב תחת `output/playwright/vocabulary/lost-found/`.

בפלייטסט אנושי: האם ילדים מבקשים את מקום המציאה לפני ניסיון המסירה? האם הייתם חוזרים לשם גם אחרי גילוי הסיפור? השוו שני תגי מקום גלויים אחרי בירור לעומת הצגתם רק בבדיקה ידנית, עם אותם חפצים ובקשות.
